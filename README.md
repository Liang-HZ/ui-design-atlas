# 前端设计原子表

> *This project is written in Chinese — the atlas itself, and every term in it. If you don't read Chinese, [Refactoring UI](https://www.refactoringui.com/) covers similar ground in English.*

**把「感觉不对」换成「12 号没过」。**

你在指挥模型做界面，但只能描述感觉——它改，你再看，你再说"还是不太对"。问题不在模型，在于**你手里没有一套能指名道姓的词**。

这份表就是那套词：6 层决策骨架、30 个能指认的概念、21 种组件、12 种页面布局，外加一份可以直接抄进项目的 `DESIGN.md`。

**[→ 在线打开（推荐）](https://ui.liangai.org/atlas)** · [落地页](https://ui.liangai.org/)

> 表里的演示是**可交互**的——滑杆能拖、标签页能切、容器能拉宽看响应式断点真的翻转。
> 这些在 GitHub 上看不到，建议直接在线打开。

## 骨架长这样

做界面是**自上而下**的一串决定。30 个概念全部挂在这 6 层上。新手最常见的卡点，是从最底层开始纠结——一上来就问"圆角该用几像素"，而那一层恰恰是最不需要你操心的。

| 层 | 你在这一层决定什么 | 挂着几个原子 |
|---|---|---|
| **L0 意图** | 这一屏给**谁**看？他要**完成什么**？ | *这层没有原子，只能你自己定* |
| **L1 信息层级** | 哪个最重要、哪些是**一组**的？ | 4 |
| **L2 骨架布局** | 怎么排？屏幕变窄怎么办？**多密**合适？ | 6 |
| **L3 组件与状态** | 用什么**零件**？没数据、出错了长什么样？ | 5 |
| **L4 数值标度** | 具体**几像素**、**什么颜色**？ | 11 |
| **L5 校验** | 看得清吗？暗色下还成立吗？ | 4 |

记住这条顺序——**先定给谁看，再定谁主谁次，再定怎么排，最后才轮到几像素**——你已经比"感觉不够精致"精确得多了。

## 它解决什么

不懂前端的人指挥模型做界面，卡点几乎总是同一个：**你只能给形容词**。

「做得高级点」「这个卡片不够精致」——这类话的歧义空间几乎是无限的，模型只能猜。而「按 02 号亲密性重排：组内 8，组间 24」是有限的。

这份表不教你成为设计师。它只做一件事：**给你一套能指认的名字**。

## 和 DESIGN.md 的关系

[`DESIGN.md`](https://github.com/google-labs-code/design.md) 是 Google Labs 维护的开源格式规范（Apache-2.0），让编码 agent 能读懂一个项目的视觉系统。

**这份表教词汇，`DESIGN.md` 是把词汇落成文件的载体。** 两者的结构几乎一一对应：

```
前言 colors        ←  09 色阶 · 10 语义色 · 11 中性色
前言 typography    ←  03 字号 · 04 字重 · 05 行高 · 07 字距
前言 spacing       ←  01 间距标度
前言 rounded       ←  08 圆角标度
## Layout          ←  21 gap · 22 Flex/Grid · 23 栅格 · 24 响应式 · 25 密度
## Components      ←  26 解剖 · 27 状态 · 28 变体矩阵 · 29 五态
```

也就是说：**前言就是 L4，正文就是 L2 / L3 / L5。L0 意图那一层它不管——那一层永远是你的。**

第四部里有一份数值填满的完整示例，复制粘贴就能用。

## 它不承诺什么

这份表**不保证**你照着说模型就会照做——那取决于模型、上下文和你提的其他要求。

它保证的是：界面不对劲的时候，你能说出**哪一号**不对，而不是"感觉不够精致"。
